# midi2brain

Plain HTML/CSS/JS piano trainer. No build step, no modules. Open `index.html` directly.

When you change a js / css file, bump its `?v=` in index.html, or browsers and the web host keep serving the cached old copy.

## JS layout
`js/*.js` are classic scripts loaded in order by `index.html`. They share one global scope, so top-level `const`/`let`/functions are visible across files. A file may only *call at load time* things from earlier files (calls inside event handlers can reach anything). Only open the file you need.

notes first: until every bar of the song has been played with the right notes (`routine-song-<id>.notesBars` → `notesOk`, `notesKnown` / `notesRight`; or a Songs tab take of ≥95% of the song with ≤2% slips) there is no tempo ladder, no speed-up, and a pass is clean when its notes are right (`b.notesPhase`); repeats: a stage whose bars are the same music (per hand, `barSigs` fingerprints) as a stage finished this session, or (hand alone / together) as bars elsewhere you have learnt, is skipped, `skipLearnt`, and a part with nothing left is done; `FAIL_LIMIT` (3) failed passes in a row set a part aside: on to the next, saved as a todo spot for next session; a part's length follows how much is in its bars (`barLoad`: onsets, chord notes, leaps; `partTo` / `fitParts` fill up to `PART_LOAD`, 1–`PART_MAX` (4) bars) and parts go in song order, each until done or set aside; in wait mode slips before the first step of a pass is played don't count, `P.firstStep` in songs.js; the last song block gets the rest of the session as its budget; done before the time is up: `moreRounds` adds the songs again, each from where it got to, sharing the time left; at the time (`timeUp`) the part you are on is finished first (up to `OVER_MAX` 5 min over), no new part or final run is started); kinds of mistakes: each pass's events are classified (`classify`: transition at a chord-shape change, leap, chord, neighbour key, hesitation, timing) and a spot that comes back picks a remedy (`remedyFor` / `applyRemedy`, at most 2 per kind and 4 per part): a drill in the Chords tab (`startDrill`: the chord change A → B → A → B or one chord shape, voiced as in the song and at the song's octaves (keyboard from the C under the lowest chord, a higher one `shift`ed up via `chooseChord(…, inv, shift)`; the hand is set with chords.js `forcedHand`, not taken from the octave), then back to the part; also before a part's first pass when the first run showed it; once per part and once per change / shape in a song block, `b.drilled`), an extra stage (`st.remedy`, with its own `range` / `speed` / `tip`: the jump's bars one hand slower, the pause spot, one hand alone for fingering, 'with the clock' in play mode for a wandering pulse), or a slower speed (hands together that slips while each hand knows it, slips that wander). Level per song from the Songs tab (bar progress + last take, `songs-takes-<id>`): new = hands separately, hands = together slowly, known = both hands from the start. Warm-up from memory: per chord / scale and hand a score (`routine-known`, clean +1, slip −2); from `KNOWN_AT` (5) it is not shown on the keyboard (keyboard.js `hideTarget` / `showOnKeys()`, also used by scales.js), a slip shows it again. `#routine-bar` shows the step on every tab; a new song shows its name as a card in the middle of the screen while the falling notes slide in (`songIntro`, routine.css). Your own settings are kept apart: at the start it copies the Songs tab (`songApp.routine.snapshot`), both hands / octave / direction / scale, and puts them back when it ends; meanwhile settings.js saves your values, not the routine's (`routineApp.normalSettings`). Saved: `routine-setup`, `routine-song-<id>` (speed, todo spots, history). Hooks: `routineApp.targetDone()` from trainer.js tryAdvance, `routineApp.miss()` from chord/scale misses, `skipItem()` from the stage tap |

## Adding a song from a sheet music PDF
1. Run `tools/pdf-shapes.ps1 -pdf <file> -outDir <scratch>` and then `tools/pdf-notes.ps1 -dir <scratch>` (PowerShell, no other dependencies). This prints exact pitches per bar from the PDF's vector noteheads. It works for notation-software exports; a scanned PDF has no vectors, so read the images instead.
   Many PDFs (Finale, LilyPond, Sibelius) draw notes as font glyphs, which the tools can't see. Then render the pages to PNG (pdf.js in headless Chrome, scale 3) and run `tools/pdf-guides.ps1`: it slices each system and labels every staff line and space with its pitch.
2. Read the rhythm, ties, voices, rests and dynamics from the score images, and write `songs/<id>.js` in the notation from songformat.js. Use JS loops or helpers for repeated bars.
3. Fingering is worked out automatically (js/fingering.js); where the score prints a finger, or the result feels wrong, fix it in the notation (`E4/1`).
4. Add the learning layer: `sections` (name, bar range, a practical tip per section), `chord` per bar, `about`, `patterns`.
5. Add the script tag to index.html, then check that the parser doesn't print any `console.warn` about bar lengths.
